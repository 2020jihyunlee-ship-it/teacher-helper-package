# cys Windows 문제 보고 — 교차검증 결과 (연구팀 공유판)

> 2026-08-25 · «Windows 문제 개발자 보고» 초안에 대한 2차 검증
> 검증 환경: Windows 11 Pro(26200) · PowerShell 5.1.26100.8655 · 별도 세션에서 독립 재현
> 표기 원칙 동일: 실측만 적고, [추정]/[미확인]은 구분한다

---

## 1. 재현 확증 — 독립 재현 성공 2건

**W3 (PS 5.1 BOM → 팩 JSON 파손) — ✅ 확증**
```
Set-Content -Encoding UTF8 실행
→ 파일 첫 바이트 efbbbf (BOM)
→ python json.load(utf-8)    : JSONDecodeError "Unexpected UTF-8 BOM"
→ python json.load(utf-8-sig): 성공
```
제안 해법(로더 `utf-8-sig` 허용 1줄)의 유효성까지 실측 확인.

**W5 (PS 5.1 stderr 예외 승격) — ✅ 확증**
```
$ErrorActionPreference='Stop' + native 명령 + 2>&1
→ stderr 첫 줄이 예외로 승격, catch 진입 · 실측 예외 타입: RemoteException
```
표기 보강 1건: catch에 잡히는 실제 타입은 `RemoteException` — 「NativeCommandError(RemoteException)」 병기 권고.

W1·W2·C1~C9는 코드 인용 기반으로 논리 검증 — 타당. W1의 «진단 계층 결함은 다른 모든 문제에 곱해진다» 논증은 그대로 유지할 것.

## 2. 범위 조정 — 사양 기인 서술 제거 (운영자 지시)

- **W4**: 현상(Defender 락)은 유지하되 「느린 PC에서는 부족할 수 있다」[추정] 문장 삭제 — 사양 서사가 섞이면 «환경 문제»로 반박당할 여지를 준다.
- **U1**: 이미 «미재현·제출 불가» 분류라 적절. 유지.

## 3. 신규 항목 후보 — 검증 중 실측 발견

**[W6 후보] PS 5.1은 BOM «없는» UTF-8 스크립트의 한글을 ANSI로 오독한다 — 실측**
한글 문자열이 든 `.ps1`을 UTF-8(무BOM)로 저장·실행 → 문자열 파손 → **파서 에러로 스크립트 전체 실행 불능**.
- W3와 정확히 반대 방향: **JSON은 BOM이 있으면 깨지고, ps1은 BOM이 없으면 깨진다.**
- 영향: 한글 주석·안내문이 든 배포 스크립트 전부. PS 7에서는 미발생 [실측].
- 제안: 표준에 **파일 종류별 인코딩 계약** 명시 — `JSON=UTF-8 무BOM · .ps1=UTF-8 BOM(또는 ASCII)`. 제약 C10 후보.

**[L3 보강] 한글 경로 — 인접 도구의 실패 실측 3건**
1. Ollama: 한글 사용자명 경로에서 모델 로딩 실패 실측 — 모델 경로 이전+env로 해결한 사례 보유
2. python http.server: 한글 파일명 URL은 percent-encoding 없이는 404 (실측)
3. python 일반: `PYTHONUTF8=1`(`-X utf8`) 필요 사례 다수
→ 결함 보고는 여전히 안 하되, L3 서술을 «잠재 위험»에서 «인접 도구 실패 실측 있음»으로 격상할 근거.

**[신규 후보 · 추정] 종료 실패 프로세스의 자원 점유 — U1 원인 후보**
일반 서버 운영에서 실측: 종료된 줄 알았던 옛 프로세스가 포트를 점유해 **새 프로세스가 조용히 실패하고 옛 상태가 응답**하는 사고 2회. cys의 named pipe·데몬 재기동에서 유사 패턴 가능 [추정].
→ U1 «필요한 정보»에 추가 권고: **재시작 시 이전 cysd 프로세스 잔존 여부(작업 관리자 실측)**.

**[미확인 추가] CRLF 변환**
`cys-dept`는 1101줄 bash — Windows에서 git `autocrlf=true` 클론 시 CRLF 주입으로 실행이 깨질 수 있다. 대상 저장소·팩의 `.gitattributes` 존재 여부 [미확인] — 확인 목록에 추가 권고.

## 4. 분류 보강 권고 — «해결한 것»의 분류가 절반뿐

현재 3군 «해결됨»은 **상류가 고친 것**(F1·F2)만 담는다.
**우리가 스스로 찾은 우회책**은 분류 없이 본문에 산재해, 해결책 대장으로서 불완전하다:

| 건 | 확보된 우회책 | 현재 위치 |
|---|---|---|
| W2 | 스크립트 헤더 명시 + 재실행 복구 운영 | 본문 «참고» 한 줄 |
| W3 | .NET `UTF8Encoding($false)` 직접 쓰기 + 임시파일 원자 교체 | 본문 «현재 우회» 한 줄 |
| W4 | 호출 간 1200ms 지연 | 본문 «현재 우회» 한 줄 |
| W5 | PS 7 사용으로 실질 회피 | 미기재 |

**개정안 (택1)**: ㉠ 건별 «해결 상태» 열 신설(상류 해결/우회 확보/미해결) ㉡ 말미에 **«확보한 해결책 목록» 절** 신설.
목적이 «찾은 방법을 잃지 않는 것»이므로 ㉡ 권고.
