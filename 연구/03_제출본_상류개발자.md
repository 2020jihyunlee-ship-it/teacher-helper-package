## W1. `cys doctor`가 검사하지 않은 항목을 `[OK]`로 집계한다 (P1)

**증상**

```
[OK  ] socket         소켓 진단은 unix 전용(skip)
[OK  ] startup-lock   락 진단은 unix 전용(skip)
요약: 7 OK · 2 WARN · 0 FAIL
```

**문제**

검사하지 **않은** 2건이 `[OK]`로 표시되고, 요약의 `7 OK`에 합산됩니다.
Windows 사용자는 **실제보다 건강한 진단 결과**를 받게 됩니다.

**영향**

Windows의 소켓은 named pipe이고, 앱 재시작·데몬 재기동 관련 문제가 집중되는 계층입니다.
그런데 바로 그 계층이 진단 대상에서 빠져 있고, **빠졌다는 사실 자체가 `[OK]`에 가려집니다.**
사용자가 문제를 겪는 순간에도 `doctor`는 "이상 없음"으로 답합니다.

이 항목을 P1로 올린 이유는 손실 크기 때문이 아니라, **진단 계층의 결함이라 다른 모든 문제의
발견을 지연시키기 때문**입니다.

**재현**

Windows에서 `cys doctor` 1회 실행.

**제안**

- skip은 `[OK]`가 아니라 `[SKIP]` 또는 `[N/A]`로 표기
- 요약 카운트에서 분리 (`7 OK · 2 SKIP · 2 WARN` 형태)
- 가능하다면 Windows named pipe 대응 진단 추가

**관련 제안 1건** — 레지스트리에 등록된 부서 작업 디렉터리가 **실제로 존재하지 않는** 상태를
실측했습니다. 어떤 명령도 이 불일치를 보고하지 않습니다. 같은 «진단 공백» 계층이므로
`doctor`에 "레지스트리 cwd 실재 검사"를 함께 추가하면 좋겠습니다.

## W2. role 없는 pane 좌석이 재기동 후 복원되지 않는다 (P1)

**사실**

데몬 재기동 시 복원은 `desired_roster.json`을 기준으로 하고, 이 로스터는 **role을 키로 하는 맵**입니다.
따라서 role 미등록 좌석은 담길 자리가 구조적으로 없습니다.

**영향**

**데몬이 한 번만 재기동해도 role 없는 좌석이 전부 사라집니다.**
부서 안에 편성해 둔 작업 좌석이 앱 재시작만으로 초기화됩니다.

플랫폼 무관한 설계 사항입니다만, Windows에서 체감이 큽니다 — 앱 재시작이 잦다는 사용자 관측이
있습니다(재현 절차는 아직 특정하지 못해 별도 보고하지 않았습니다). 재시작 빈도가 높을수록
노출이 잦아집니다.

**제안**

- 로스터 키를 `(role, title)` 복합키로 확장, 또는
- role 없는 좌석을 위한 별도 복원 목록

**참고** — 이 한계는 관련 배포 스크립트 주석에도 이미 명시되어 있어, 알려진 설계 사항으로 이해하고
있습니다. 다만 부서 편성을 파일 선언으로 재현하려는 쪽에서는 이 지점이 가장 큰 장애입니다.

## W3. PowerShell 5.1이 붙이는 BOM으로 팩 JSON이 파손된다 (P2)

**증상**

PS 5.1의 `Set-Content -Encoding UTF8`은 **BOM을 붙입니다.**
팩의 python 측 `json.load`가 이를 읽지 못해 설정 파일이 깨집니다.

**영향 범위**

PS 5.1은 Windows 기본 탑재 셸이라, PowerShell로 팩 JSON(카탈로그·레지스트리)을 쓰는
**모든 경로**에 같은 위험이 있습니다. Windows 안내 문서가 `Set-Content`를 예시로 들면
그대로 재발합니다.

**현재 상황**

이 문제를 아는 스크립트들은 `Set-Content`를 피하고 .NET `UTF8Encoding($false)`로 직접 쓴 뒤
임시파일+원자 교체를 합니다. 즉 **개별 스크립트가 각자 방어**하고 있는 상태입니다.

**제안**

python 로더에서 `utf-8-sig`를 허용하면 한 줄로 근본 해결됩니다. 수정비용이 가장 낮은 항목입니다.

## W4. 백신 락으로 cys 연속 호출이 실패한다 (P2)

**증상**

cys 프로세스를 짧은 간격으로 연속 호출하면 실패합니다. Defender가 기본 활성인 환경에서
발생하며, 예외 등록을 한 사용자만 비껴갑니다.

**현재 우회**

호출 사이에 **1200ms 고정 지연**을 넣는 방식이 쓰이고 있습니다.

**영향**

부서 여러 개와 좌석 여러 개를 만드는 초기 편성 과정이 지연만으로 십수 초 늘어납니다.
고정값이라 느린 PC에서는 여전히 부족할 수 있고, 빠른 PC에서는 불필요한 낭비입니다.
(느린 PC에서의 실패는 추정이며, 실측하지 못했습니다.)

**제안**

- 고정 지연 대신 재시도 + 백오프
- 또는 락으로 인한 실패를 **구분 가능한 종료코드**로 노출해, 호출자가 재시도를 판단할 수 있게

## W5. PowerShell 5.1에서 native 명령 stderr가 예외로 승격된다 (P3)

**증상**

`$ErrorActionPreference = 'Stop'` + `2>&1` 조합에서 native 명령의 stderr **첫 줄**이
`NativeCommandError`로 터집니다. cys는 정상 진행 정보도 stderr로 내보내므로,
**정상 동작이 스크립트 중단으로 이어집니다.**

**영향**

일반 사용자는 겪지 않습니다. cys를 PowerShell 스크립트로 감싸는 경우에만 해당합니다.

**제안**

- Windows 스크립팅 문서에 이 함정을 명시, 또는
- 정보성 출력을 stdout으로 분리 (다만 기존 소비자 영향이 있을 수 있어 문서 보강이 안전해 보입니다)

## 보고에서 제외한 것

정확성을 위해 아래는 의도적으로 제외했습니다.

- **이 PC의 사용 이력에서 비롯된 것** — 등록부-실물 불일치, 부서 등록 수가 상한에 근접한 상태,
  한글 사용자명 경로. 새 설치에서는 발생하지 않아 공통 문제로 보고하지 않습니다.
  (다만 «진단 공백» 관점의 일반화 가능 부분만 W1에 함께 적었습니다.)
- **재현하지 못한 것** — 앱 재시작 후 스크롤 이상 등의 사용자 관측이 있으나, 재현 절차를
  특정하지 못해 보고하지 않습니다. 확인되면 별도로 올리겠습니다.

## 이미 해결된 것 (확인 정보)

커뮤니티 문서(2026-07-15)가 제기했던 Windows 결함 2건은 **0.14.7에서 코드 실측 결과 모두
해결되어 있음을 확인**했습니다.

- preflight `C53` — 실행 확장자 제거 + 소문자 비교로 수정됨
- safe_path 하 형제 모듈 import — 경로 가드 추가로 수정됨 (fail-open이던 항목)

수정에 감사드립니다. 커뮤니티 문서에는 아직 «미반영»으로 적혀 있어, 그쪽에도 별도로
확인 사실을 전달할 예정입니다.
