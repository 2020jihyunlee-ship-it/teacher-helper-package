## 1. 재현 확증 — 이 PC에서 독립 재현 성공 2건

### W3 (PS 5.1 BOM → 팩 JSON 파손) — ✅ 확증
```
PS 5.1.26100.8655 에서 Set-Content -Encoding UTF8 실행
→ 파일 첫 바이트 efbbbf (BOM) 확인
→ python json.load(encoding='utf-8')  : JSONDecodeError "Unexpected UTF-8 BOM (decode using utf-8-sig)"
→ python json.load(encoding='utf-8-sig'): 성공
```
제안된 해법(로더 `utf-8-sig` 허용 1줄)의 유효성까지 실측 확인.

### W5 (PS 5.1 stderr 예외 승격) — ✅ 확증
```
$ErrorActionPreference='Stop' + native 명령 + 2>&1
→ stderr 첫 줄이 예외로 승격, catch 진입
→ 실측 예외 타입: RemoteException
```
보강 제안 1건: 문서의 «NativeCommandError» 는 에러 레코드 명칭이고 catch에 잡히는 실제 예외 타입은 `RemoteException` — **「NativeCommandError(RemoteException)」 병기** 권고. 개발자가 재현 시 타입명 불일치로 갸웃하지 않게.

W1·W2·C1~C9 는 코드 인용 기반으로 논리 검증만 수행 — 타당. 특히 W1의 «진단 계층 결함은 다른 모든 문제에 곱해진다» 논증은 유지할 것.

## 3. 신규 항목 후보 — 검증 중 실측 발견

### [W6 후보] PS 5.1은 BOM «없는» UTF-8 스크립트의 한글을 ANSI로 오독한다 — 실측
W5 재현 실험 중 실제로 걸린 건: 한글 문자열이 든 `.ps1`을 UTF-8(무BOM)로 저장·실행하자
문자열이 CP949로 오독·파손되며 **파서 에러로 스크립트 전체 실행 불능**.
- **W3와 정확히 반대 방향**: JSON은 BOM이 있으면 깨지고, ps1은 BOM이 없으면 깨진다.
- 영향: 한글 주석·메시지가 든 배포 스크립트(setup.ps1 계열) 전부가 대상. ASCII로만 쓰면 회피되나 한글 안내 출력이 필요한 스크립트는 함정.
- 제안: 표준에 **파일 종류별 인코딩 계약** 명시 — `JSON=UTF-8 무BOM · .ps1=UTF-8 BOM(또는 ASCII)`.
- 분류 의견: 1군(공통) P2~P3. PS 7에서는 미발생(기본 UTF-8 해석) [실측 — 본진 PS7 환경에서 동일 스크립트 정상].

### [L3 보강] 한글 경로 — «인접 도구 실패 실측» 증거 3건 (본진 보유)
L3의 [미검증]을 «인접 도구에서는 실패 실측 있음»으로 격상할 근거:
1. **Ollama**: 한글 사용자명 경로에서 모델 로딩 실패 — 실측·해결(모델 경로를 `C:\ollama\models`로 이전 + `OLLAMA_MODELS` env). 동봉 아닌 외부 도구 연동 시 위험이 실재한다는 증거.
2. **python http.server**: 한글 파일명 URL은 percent-encoding 없이는 404 (2026-08-25 실측).
3. **python 일반**: 한글 경로·출력 환경에서 `PYTHONUTF8=1`(`-X utf8`) 필요 사례 다수 (킹클 봇 운영 실측).
→ 결함 보고는 여전히 하지 않되, 추적 항목의 서술을 «잠재»에서 «인접 실측 있음»으로.

### [신규 후보 · 추정] 종료 실패 프로세스의 자원 점유 — U1의 원인 후보
본진 실측(2026-08-24~25, cys 아님·일반 서버 운영): 종료된 줄 알았던 옛 프로세스가 포트를 점유해
**새 프로세스가 조용히 실패하고 옛 상태가 응답**하는 사고 2회.
cys의 named pipe·데몬 재기동에서 유사 패턴(옛 cysd 잔존 → 신규 기동 실패 또는 구 상태 응답) 가능 [추정].
→ U1 «필요한 정보» 목록에 추가 권고: **재시작 시 이전 cysd 프로세스 잔존 여부(작업 관리자 실측)**.

### [미확인 추가 권고] CRLF 변환
`cys-dept`가 1101줄 **bash**인데, Windows에서 git `autocrlf=true`로 클론되면 bash에 CRLF가 주입되어
실행이 깨질 수 있다. 대상 저장소·팩의 `.gitattributes` 존재 여부 [미확인] — 확인 목록에 추가 권고.

## 4. 분류 보강 — 오너 재확인 지시 반영 (중요)

**질문**: «해결했던 것»이 별도 분류돼 있는가 → **절반만.**
- 3군 «해결됨» = **상류가 고친 것**(F1·F2)만 담고 있다.
- **우리가 스스로 방법을 찾아 우회한 것**은 분류가 없고 1군 본문에 산재:

| 건 | 우리가 확보한 방법 | 현재 위치 |
|---|---|---|
| W2 | setup.ps1 헤더 명시 + 재실행 복구 운영 | 1군 «참고» 한 줄 |
| W3 | .NET `UTF8Encoding($false)` 직접 쓰기 + 임시파일 원자 교체 | 1군 «현재 우회» 한 줄 |
| W4 | 호출 간 1200ms 지연 | 1군 «현재 우회» 한 줄 |
| W5 | (본진) PS 7 사용으로 실질 회피 | 미기재 |

**개정 권고 (택1)**:
- ㉠ 각 건에 **해결 상태 열** 신설 — `상류 해결 / 우리 우회 확보(방법·위치 병기) / 미해결`
- ㉡ 문서 말미 **«우리가 확보한 해결책 목록» 절** 신설 (W2·W3·W4·W5 우회법 집약)
→ 목적이 «찾은 방법을 잃지 않는 것»이므로 ㉡이 더 직관적이라는 게 카이 의견. 샤론 판단으로 확정.
